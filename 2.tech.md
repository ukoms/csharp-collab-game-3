# Collab 03 - wskazówki techniczne

## 1. Pojęcia i przykłady

- Każdy listing to kompletny, osobny program konsolowy .NET 10. 
- Zastępuje Program.cs w **oddzielnym projekcie prób poza katalogiem gry**. Nie łącz przykładów w jednym pliku.
- W przykładzie instrukcje programu są nad klasą. W oddawanej grze klasa ma osobny plik.

### 1.1. Klasa, pole, konstruktor, właściwość i metoda

- `new Pojemnik(2)` tworzy obiekt i wywołuje konstruktor z argumentem 2.
- `_limit` jest prywatnym polem obiektu; `limit` jest parametrem konstruktora.
- Konstruktor ma nazwę klasy i nie deklaruje typu wyniku.
- `Ilosc` jest automatyczną właściwością. `get; private set;` pozwala na publiczny odczyt, ale zapis wewnątrz klasy.
- `Dolej()` to metoda instancji. Działa na obiekcie po lewej stronie kropki. `void` oznacza brak zwracanej wartości, nie brak działania.
- Warunek metody pilnuje limitu. Samo `private set` nie waliduje danych.
- Klasa nie wypisuje komunikatów. Kod korzystający z obiektu decyduje, gdzie pokazać wynik.


### Przykład

```csharp
Pojemnik pierwszy = new Pojemnik(2);
Pojemnik drugi = new Pojemnik(1);
pierwszy.Dolej();
pierwszy.Dolej();
pierwszy.Dolej();
Console.WriteLine(pierwszy.Ilosc);
Console.WriteLine(drugi.Ilosc);
class Pojemnik
{
    private int _limit;
    public int Ilosc { get; private set; }
    public Pojemnik(int limit)
    {
        if (limit < 0) limit = 0;
        _limit = limit;
        Ilosc = 0;
    }
    public void Dolej()
    {
        if (Ilosc < _limit) Ilosc = Ilosc + 1;
    }
}
```

Wynik:

```text
2
0
```

### 1.2. Wynik metody i wcześniejsze zakończenie

- `bool` przed nazwą oznacza wynik prawda/fałsz. `return` kończy bieżące wywołanie.
- Metoda zwracająca `bool` może zmieniać stan, jeśli tak mówi kontrakt. Wydaj robi to tylko przy sukcesie.
- W dzienniku `CzyOdwiedzono` ma wyłącznie odczytywać; `Odwiedz` ma zmieniać flagę.


### Przykład

```csharp
Magazyn magazyn = new Magazyn();
Console.WriteLine(magazyn.Wydaj());
Console.WriteLine(magazyn.Wydaj());
Console.WriteLine(magazyn.Zapas);
class Magazyn
{
    public int Zapas { get; private set; } = 1;
    public bool Wydaj()
    {
        if (Zapas == 0)
        {
            return false;
        }
        Zapas = Zapas - 1;
        return true;
    }
}
```

Wynik:

```text
True
False
0
```

### 1.3. Referencja i niezależne instancje

- `b = a` kopiuje referencję. Dwie zmienne mogą wskazywać ten sam obiekt.
- Drugie `new` tworzy drugi obiekt. Każda instancja dziennika tworzy własne tablice.
- Pola odkryć i historii pozostają bez `static`. Nie przekazuj obu obiektom tej samej tablicy i nie zwracaj tablic do samodzielnej zmiany.


### Przykład

```csharp
Znacznik a = new Znacznik();
Znacznik b = a;
Znacznik c = new Znacznik();
b.Oznacz();
Console.WriteLine(a.Aktywny);
Console.WriteLine(c.Aktywny);
class Znacznik
{
    public bool Aktywny { get; private set; }
    public void Oznacz()
    {
        Aktywny = true;
    }
}
```

Wynik:

```text
True
False
```

### 1.4. Właściwość obliczana

- Getter z ciałem może obliczać wynik podczas odczytu. Zmienna lokalna wynik zaczyna tutaj od zera przy każdym odczycie.
- `LiczbaOdwiedzonych` ma zliczać flagi. Nie przechowuj dodatkowej, niezależnie zwiększanej liczby odkryć.
- `LiczbaWpisow` jest natomiast przechowywaną liczbą zajętych miejsc: 0–3. Nie jest liczbą wszystkich czynności.


### Przykład

```csharp
Rachunek rzecz = new Rachunek();
Console.WriteLine(rzecz.SumaCen);
class Rachunek
{
    private int[] _ceny = { 4, 7 };
    public int SumaCen
    {
        get
        {
            int wynik = 0;
            foreach (int cena in _ceny)
            {
                wynik = wynik + cena;
            }
            return wynik;
        }
    }
}
```

Wynik:

```text
11
```

### 1.5. Sprawdzenie zakresu przed odczytem

- Tablica długości n ma indeksy 0..n−1. `||` oznacza logiczne „lub”.
- Najpierw odrzuć błędny argument, potem odczytaj element. W przykładzie argument jest indeksem; w metodach odwiedzin jest numerem pokoju 1–4.
- Zwrot `false` dla błędnego argumentu jest umową tego ćwiczenia.


### Przykład

```csharp
TablicaMiejsc tablica = new TablicaMiejsc();
Console.WriteLine(tablica.CzyZajete(-1));
Console.WriteLine(tablica.CzyZajete(1));
Console.WriteLine(tablica.CzyZajete(2));
class TablicaMiejsc
{
    private bool[] _zajete = { false, true };
    public bool CzyZajete(int indeks)
    {
        if (indeks < 0 || indeks >= _zajete.Length)
        {
            return false;
        }
        return _zajete[indeks];
    }
}
```

Wynik:

```text
False
True
False
```

### 1.6. Konstruktor i reset

- Reset zmienia stan istniejącego obiektu. Konstruktor może wywołać tę samą operację, aby nie powielać inicjalizacji.
- `Start()` gry resetuje także energię i przedmioty. `Reset()` dziennika dotyczy tylko dziennika.
- W dzienniku po resecie: tylko pierwszy pokój odkryty, puste teksty i zero wpisów.


### Przykład

```csharp
Licznik licznik = new Licznik();
Licznik drugaNazwa = licznik;
licznik.Zwieksz();
Console.WriteLine(drugaNazwa.Wartosc);
licznik.Reset();
Console.WriteLine(drugaNazwa.Wartosc);
class Licznik
{
    public int Wartosc { get; private set; }
    public Licznik()
    {
        Reset();
    }
    public void Zwieksz()
    {
        Wartosc = Wartosc + 1;
    }
    public void Reset()
    {
        Wartosc = 0;
    }
}
```

Wynik:

```text
1
0
```

### 1.7. Null, pusty napis i Trim

- `string?` dopuszcza brak wartości; nie usuwa potrzeby sprawdzenia `null`.
- Najpierw sprawdź `null`, potem zastosuj `Trim()` i sprawdź pusty wynik. `Trim()` zwraca nowy wynik, nie modyfikuje napisu w miejscu.
- Odmowa nie może zmieniać wcześniejszych danych. Do treści wpisu nie stosuj `ToLowerInvariant()`; to normalizacja komend.


### Przykład

```csharp
Etykieta etykieta = new Etykieta();
etykieta.Ustaw("  Most  ");
Console.WriteLine(etykieta.Tekst);
etykieta.Ustaw(null);
etykieta.Ustaw("");
etykieta.Ustaw("   ");
Console.WriteLine(etykieta.Tekst);
class Etykieta
{
    public string Tekst { get; private set; } = "";
    public void Ustaw(string? tekst)
    {
        if (tekst == null)
        {
            return;
        }
        string oczyszczony = tekst.Trim();
        if (oczyszczony == "")
        {
            return;
        }
        Tekst = oczyszczony;
    }
}
```

Wynik:

```text
Most
Most
```

### 1.8. Pojemność i liczba zajętych miejsc

- Zainicjalizuj miejsca historii pustymi napisami. Samo `new string[3]` pozostawia elementy `null`.
- Pętla odczytu korzysta z liczby zajętych miejsc, nie z pojemności.
- csharp-collab-3-I pokazuje jeden zapis do wolnego miejsca. Nie jest gotową obsługą dowolnej liczby dopisań.


### Przykład

```csharp
string[] etykiety = { "", "", "" };
int liczbaEtykiet = 0;
Console.WriteLine(etykiety.Length);
Console.WriteLine(liczbaEtykiet);
etykiety[liczbaEtykiet] = "Most";
liczbaEtykiet = liczbaEtykiet + 1;
for (int i = 0; i < liczbaEtykiet; i = i + 1)
{
    Console.WriteLine(etykiety[i]);
}
```

Wynik:

```text
3
0
Most
```

### 1.9. Pełna historia i kierunek przesuwania

- Dla A/B/C kolejny wpis D ma dać B/C/D, a kolejny E - C/D/E.
- Przy wolnym miejscu dopisz tekst i zwiększ licznik. Przy pełnej tablicy przesuń elementy ku początkowi, dopisz tekst na końcu i zachowaj licznik 3.
- Sprawdź tekst **przed** jakąkolwiek zmianą historii.
- csharp-collab-3-D pokazuje tylko przesunięcie pełnej tablicy pomiarów. Obsługę niepełnej historii i integrację napiszesz sam.


### Przykład

```csharp
int[] ostatniePomiary = { 8, 4, 9 };
int nowyPomiar = 6;
for (int i = 0; i < ostatniePomiary.Length - 1; i = i + 1)
{
    ostatniePomiary[i] = ostatniePomiary[i + 1];
}
ostatniePomiary[ostatniePomiary.Length - 1] = nowyPomiar;
foreach (int pomiar in ostatniePomiary)
{
    Console.WriteLine(pomiar);
}
```

Wynik:

```text
4
9
6
```

- Osobny plik `DziennikWyprawy.cs` w tym samym projekcie co Program.cs, na tym etapie bez własnej przestrzeni nazw (`namespace`). Plik klasy nie zawiera instrukcji najwyższego poziomu ani drugiego Main.

| Składowa publiczna | Umowa |
|---|---|
| `DziennikWyprawy()` | Konstruktor bez parametrów ustanawia stan taki jak Reset. |
| `int LiczbaOdwiedzonych { get; }` | Tylko odczyt; wynik obliczany z prywatnych flag przez pętlę. Nie jest drugim, niezależnie aktualizowanym licznikiem. |
| `int LiczbaWpisow { get; private set; }` | Liczba zajętych pozycji dziennika 0–3; klient nie może jej przypisać. |
| `void Odwiedz(int numer)` | Dla 1–4 oznacza pokój; ponowna wizyta niczego nie zwiększa. Dla numeru spoza zakresu nic nie zmienia. |
| `bool CzyOdwiedzono(int numer)` | Odczyt flagi; dla numeru spoza 1–4 zwraca false. |
| `void DodajWpis(string? tresc)` | Ignoruje null, pusty tekst i same spacje. Poprawny tekst zapisuje po Trim. Przy pełnych 3 wpisach usuwa najstarszy, zachowując kolejność. |
| `string PobierzWpis(int indeks)` | Zajęte wpisy mają indeksy 0..LiczbaWpisow-1, od najstarszego. Dla innych indeksów zwraca pusty napis; nie rzuca wyjątku w tym ćwiczeniu. |
| `void Reset()` | Cztery flagi odkryć: tylko pokój 1 odwiedzony; dziennik pusty, LiczbaWpisow=0. Czyści także stare teksty w tablicy. Nie tworzy drugiego obiektu. |

- W tabeli opisano API, nie gotowy kod do wklejenia. Getter LiczbaOdwiedzonych wymaga własnego ciała obliczającego wynik.
- Prywatna tablica wpisów ma stałą długość 3. Zainicjalizuj wszystkie elementy pustymi napisami; nie polegaj na niejawnych null w nowej tablicy stringów.
- W minimum nie wprowadzamy własnej obsługi wyjątków, dziedziczenia, `List`, LINQ, zapisu do plików ani pakietów testowych. Ich użycie nie jest potrzebne do wykonania tego collaba.

### Reguły wpisów

- Dokładnie jeden wpis po każdym udanym `lewo`, `prawo`, `karta`, `bezpiecznik`, `napraw` i `wyjdz`.
- Wpis ruchu wskazuje miejsce docelowe; wpis akcji opisuje jej skutek. Treść może pasować do fabuły, ale znaczenie musi być jednoznaczne.
- Wpis dodaj po zaakceptowaniu zmiany i przed dotychczasowym ZakonczTure, również dla ostatniej czynności kończącej rozgrywkę.
- Nie zapisuj `start`, informacji, nieznanych komend, pustego wejścia, odmów ani samych komunikatów o końcu gry. Start czyści historię, nie dopisuje własnego wpisu.
- Oznaczenie odwiedzin samo nie dopisuje zdarzenia - powrót do znanego pokoju nadal jest udanym ruchem i wymaga wpisu od obsługi ruchu.
- Klasa nie używa Console, nie nalicza energii i nie rozstrzyga zwycięstwa. Program wyświetla odczytane dane.

### Git - obowiązkowy przebieg

- Przed pracą ustalcie nazwę głównej gałęzi w GitHubie i README. Przykład używa `master`, zgodnie z repozytorium bazowym; przy `main` zamieńcie nazwę we wszystkich poleceniach. Nie twórzcie przypadkowo drugiej głównej gałęzi.
- Pracujcie w katalogu z `.csproj`; jeśli gra działa, zakończcie ją przed poleceniami terminala.

```bash
git status
git switch master
git pull --ff-only
dotnet build
git switch -c feature/collab-zadanie
```

- `feature/collab-zadanie` zastąp własną nazwą, np. `feature/c03-odkrycia` albo `feature/c03-dziennik`. Każda osoba używa innej gałęzi. Zacznij od czystego katalogu; własne zmiany zapisz przed przełączeniem.
- Po małej zmianie: `git diff`, `dotnet build`, `dotnet run`, właściwe próby, zamknięcie gry.
- Dodaj jawnie zmienione pliki przez `git add NAZWA_PLIKU` (to miejsce na prawdziwą nazwę), obejrzyj `git diff --staged`, zrób commit opisujący zmianę i `git push -u origin NAZWA_GALEZI`.
- Otwórz PR do faktycznej głównej gałęzi; kolega sprawdza warunki, reset i koszt. Integrator scala przez GitHub po jednej gałęzi; nie wykonuje drugiego merge tej samej zmiany lokalnie.
- Po każdym scaleniu pobierz główną gałąź do czystej kopii i wykonaj build oraz właściwe próby. Własną niezakończoną gałąź aktualizuj przez `git fetch origin`, potem `git merge origin/master` po zapisaniu swojej pracy w commicie.
- Jeśli wystąpi konflikt, przeczytaj obie wersje z autorem i sprawdź wynik. Bez force-push i resetowania w ciemno. `pull --ff-only` może odmówić przy rozbieżności - wtedy sprawdź historię.
- Końcowy tag tworzy tylko integrator na odebranej głównej gałęzi; nazwa tagu jest podana w briefie. Nie nadpisuj istniejącego tagu: użyj kolejnej wersji.
- Po odbiorze integrator wykonuje `git tag collab-03-core-v1` i `git push origin collab-03-core-v1`. Jeśli ten tag już istnieje, uzgodnij kolejną nazwę, np. `collab-03-core-v2`, i użyj jej w obu poleceniach oraz przekazaniu.

## 6. Dodatki opcjonalne

- Dodatkowy widok wpisów od najnowszego pod osobną komendą; zwykłe dziennik nadal pokazuje od najstarszego. Wykorzystaj pętlę malejącą, bez zmiany danych.
- Tematyczna ramka dziennika lub numerowanie widocznych wierszy.
- Podsumowanie tekstowe łączące odkrycia i istniejące trzy wpisy, bez zapisu do pliku.
- C4 działa na samym R2.1–R2.6. Nie wymaga dodatkowego widoku, drugiej historii, pełnego logu, dat ani zapisu.
